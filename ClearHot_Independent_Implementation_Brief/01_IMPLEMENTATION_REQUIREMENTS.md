# Binding implementation requirements — same task for both agents

## 0. Objective and priorities

Deliver an independently buildable, local Mac thermal-workbench improvement **and a genuinely runnable, controlled offline CNN feedback loop**. Start from `starting_point/`. Preserve the working local player and actual classical baselines; improve the evaluation and implement training, validation, review, opt-in promotion, inference and rollback end to end.

Priority if time or tools are constrained: (1) preserve local playback, input correctness and truthful results; (2) deliver a small but fully functioning offline training/evaluation/promotion loop using synthetic data and a real-paired-data import path; (3) connect its output to video review; (4) improve detailed comparison and hard-negative tests. A complete small model with honest limitations beats a large UI with fake data or a theoretical feedback diagram. If something cannot be completed or tested, state it as unfinished; do not present placeholders as implementation.

## 1. Preserve a runnable local baseline

1. Retain `ClearHot_Local.html` or an equally straightforward local Mac launch path. The user must be able to open a local file, see the original raw fixed-window reference and a selected processed stream, play from any frame to the end, pause, seek, restart, step and change the processing method. Never impose an arbitrary 60-frame limit. Explicitly distinguish file frame count from target playback fps; the actual file format/rate is unverified.
2. The original Argos 2 implementation in `starting_point/src/argos/thermalPipelineEngine.ts`, its original default configuration, and CNN-disabled behavior must remain selectable as the reference. Retain the other original methods Argos 1/3 and Claude A/B/C as well as the current newer Claude classical pipeline. They must use the same explicitly decoded current frame and shared source/ROIs; maintain each original's real temporal context and native-display behavior or clearly label any modified method as a new variant. Do not relabel a rewrite as untouched. Preserve the original files/archives untouched for provenance.
3. Keep or improve end-to-end reproducible comparison, including raw reference, identical frame index, configurable locked reference window, ROIs, per-object review, blind candidate labels and session exports. Explicitly distinguish **native method output** (different AGC and tone mapping) from any optional **common-tone controlled output**; never say all final images share one tone curve unless they actually do. If a method cannot be fairly remapped to a shared intermediate domain, say so rather than inventing one. Preserve both full-resolution operation and the no-deliberate-skip playback option; report when playback cannot keep up. Never infer 25 fps from a single internal call.
4. Temporal behavior: keep state per method while sequentially playing; reset on source, decoder, method, nonconsecutive seek and relevant configuration changes. Clearly state what pause/resume does. Tests must catch stale frame/source metadata and stale temporal buffers. The original Claude B is offline/non-causal at startup: label it, retain the original if comparing it, and separately label/test any causal variant. Do not let its frame window cross a train/validation/test boundary.
5. The recording must remain local. Prefer the current standalone browser viewer plus a separate optional local training/inference CLI. If introducing a local service, bind to loopback by default, use a random bearer token or equivalent for every state-changing and sensitive read endpoint, validate payload sizes and origins, support clean shutdown and never expose public endpoints; document the privacy implications. Do not use the unauthenticated Next.js APIs in the reference submissions as a starting solution. Avoid remote fonts, CDNs, telemetry, analytics, API calls and auto downloads during use. Verify offline operation.

## 2. Format, frame integrity and provenance

- Keep 14-bit-in-uint16 support with explicit endianness, width/height, file-level header and right-shift hypotheses. Validate indices and dimensions. Reject a source smaller than one complete frame and never silently zero-pad or wrap an invalid read. Warn on remainder bytes; explain this can mean an unsupported format. Do not assert that size divisibility proves layout.
- Existing originals are explicitly 14-bit. Either retain the honest 14-bit restriction for their comparison, or add wider-bit support with a documented, user-approved, non-silent compatibility conversion and separate true-width reference/processing path. Do not advertise full 16-bit while shifting/truncating it. Test little/big endian, high-bit masking, shift, header, exact/remainder/short file and first/last/invalid indices.
- Compute a **full-file SHA-256** using streaming/chunks; if an optional sampled fingerprint exists, name it distinctly and never call it full SHA-256. Show progress/cancellation. Preserve raw data; no in-place edits. Associate source hash, selected file, frame index, decoder settings, raw pixels, stage settings, window, model identity and timestamps atomically with saved observations or inference outputs. Source, config and seek changes must invalidate pending/stale results.
- Document which fields/notes may be sensitive, where they are saved and how to delete them. Do not transmit the sample or large local datasets.

## 3. Classical processing, ROI measurement and evaluation

- Implement a useful, independently selectable candidate or controlled variants building on the original Argos 2. Possibilities include bounded edge-aware guided/bilateral base-detail with noise-aware coring, a locked monotone window/highlight strategy, conservative local contrast, and a separately labelled causal temporal version. Pick and document concrete settings; keep raw and original Argos 2 unchanged. Do not claim improvement or deploy automatically without evaluation.
- Implement explicit, genuine stage ablation. The views must include raw fixed-window, line-only, tone-only, detail-only where technically separable, combined classical, and opt-in CNN. If original Argos 2 fuses stages and a truly isolated stage cannot be constructed without altering the original, label it a **modified ablation** and separately retain the original. Test that toggling a stage changes a suitable structured fixture and that the ablation uses a single explicit fixed reference window. Never claim that the old Argon “detail only” worked: the review found it did not.
- Keep manual ROIs for animal, bridge, nearby backgrounds, thin structure and flat stripe areas; support multiple examples and per-object scores/notes. Report raw counts, robust spread, clipping and local-background contrast separately from processed counts and 8-bit display values. No categorical 1.5σ/2.5σ/3σ verdicts, temperature inference or assumption that an animal must be brighter. Spatial processing may change ordering; show when this can occur. Auto-labeled semantic brightening is not acceptable.
- Evaluation needs generated scenes with **known clean truth** and hard negatives: no-stripe false correction, alternating strong stripes, true full-height vertical/horizontal line/wire, small targets, texture, motion/occlusion, fixed-pattern noise and similar-brightness objects. Report PSNR/SSIM only where clean truth exists, noise/stripe reduction, individual thin-feature retention, clipping, halos and false enhancement; show failures and tradeoffs, not only averages. Values >1 for contrast retention may be oversharpening, not automatically better. For real footage without clean truth use labeled no-reference proxies and blinded visual review, not invented PSNR or unsupported temperature claims.
- Implement reproducible evaluation records: frame/sequence provenance and hashes, train/validation/test split, selected reviewer identity or pseudonym, method/code/config/decoder/model versions, seed and device, clip settings, exact metric definitions, per-case results, timing conditions and failures. Export JSON/CSV locally; no seeded fake votes or prewritten verdicts. If persistence fails, report failure and do not show “saved” or “vote recorded.”
- Blinding is practical rather than cryptographic: neutral/randomized order **from the first trial**, no method names until review is complete, tie/uncertain option, and no fabricated reviewers. If displaying simple intervals, describe reviewer/scene correlation and sampling limits; do not rank generally from tiny repeated trials.

## 4. Implement the controlled offline CNN loop — actual code, not a plan

### 4.1 Data ingestion and split management

Provide a command-line or equivalent local interface that accepts:

- A small, deterministic synthetic **known-clean** fixture included/generated in the project, with intentionally generated realistic-ish noise/stripes, true thin features and moving targets. Its training and validation scenes must be separate by generator scene identity or sequence, not merely shuffled neighboring frames. Label every result synthetic.
- A **real local data path** for user-curated pairs, e.g. raw noisy input and separately supplied trusted aligned reference in the same documented count domain, including recording IDs, frame indices, decoder configuration and verified full-file hashes. Provide manifest schema, validation, examples and an importer without requiring the recording in the deliverable. Require the human to attest source/target provenance and alignment; the tool cannot independently prove a target is clean or calibrated. Reject missing/mismatched frame dimensions, hashes, unsupported modes and duplicate recordings across disjoint splits. Never silently treat a single unlabeled frame, another noisy adjacent frame, a blurred image or the current model's prediction as clean ground truth.
- A dataset/version manifest that records source and target identity, condition/device/recording grouping where available, preprocessing and provenance. A sample may have annotations/ROIs, but a preference or object label alone is **not** a clean denoising target.

Provide distinct train and validation sets grouped by recording/scene/device as far as available, plus a separately reserved untouched final test set. Prevent exact content hashes from being assigned to more than one split. Enforce sequence boundaries and context overlap; reject obvious leakage. Declare limitations: code cannot prove that two different file hashes are independent scenes/devices, and a single recording yields exploratory time-block results only. Avoid repeatedly using the final test to choose a model.

### 4.2 Actual trainable model

- Implement a **real trainable CNN** appropriate for small 14-bit thermal images/patches, with optimizable convolution kernels and backpropagation—not fixed filters, hand-tuned mix weights, or fake training progress. Keep it modest enough for a Mac CPU and optionally Apple Silicon MPS. Provide explicit reproducible commands, small default synthetic demo and configurable iterations/seeds; no model downloads or GPU requirement. Dependency installation must state platform/Python versions, approximate download/disk requirements and compatibility; normal training/inference is offline.
- Clearly define what the network predicts, exact input/output domain, normalization, clipping, tile/overlap handling, channel layout, units and insertion point. Classical correction, neural residual restoration, display transforms and calibrated quantities must not be conflated. Provide an identity/no-CNN option. A preference for apparent brightness is not a license to hallucinate objects or temperature.
- Save real checkpoint weights and optimizer/config state. Show actual train/validation losses and steps, finite-value checks, reproducible seeds and model/architecture hash. Record package version, code hash, split/data manifest and training parameters. If a run fails or prerequisites are missing, visibly fail rather than claiming training succeeded. Synthetic training is a functional demonstration, not proof of real-scene quality.

### 4.3 Candidate evaluation, review, promotion and rollback

- Implement an executable validation/evaluation command that compares the **same inputs** against identity/raw and the frozen actual Argos 2/classical baseline as well as the current promoted checkpoint when one exists. If neural processing acts at a different pipeline stage/domain, make the mapping explicit and use fair common comparisons; retain each method's native display separately. Do not compare mismatched ADU and 8-bit values as if equivalent.
- Include quantitative metrics appropriate to available truth and safety gates for no-stripe false correction, thin line/small object preservation, clipping, overshoot/halos and motion artifacts; show per-scene results and failure cases, not just average loss. Use deterministic synthetic acceptance fixtures with known outcomes. Gate thresholds must be declared/configurable and justified as engineering checks, not universal scientific constants. Do not claim real data generalization from toy fixtures.
- Implement a model registry on the local disk with separate `candidate`, `validated`, and `promoted/active` identities, immutable checkpoint IDs/hashes, validation report, approval record, previous-version pointer, and atomic promotion/rollback. A candidate which fails a mandatory guard must not promote. A human must explicitly approve a candidate even if it passes; no auto-promote on lower training loss or a click. Logs must distinguish “simulated/demo,” “candidate,” “validated,” “approved,” “active,” and “rejected.”
- Enable another cycle with more **curated** data: show how new observations/labels and new data versions enter a future training run, how the baseline is preserved, and how validation is rerun. Evaluator feedback can identify frames for review, but should not automatically become clean targets or training labels. Do not train on final-test material.
- Automated end-to-end test must demonstrate at least **two cycles** on tiny synthetic fixtures: train a first actual model and save its checkpoint; evaluate; simulate explicit approval/promotion for an eligible candidate; run a second candidate; exercise a deliberately failing/regressing case that is rejected; verify rollback and restart restore the exact previous active model. If a promotion fixture uses special test thresholds, identify them as test-only, not product safety evidence. The final-test path must be separately gated and immutable until explicitly invoked; record every invocation.

### 4.4 Connect the model to actual video review

A trainer that ends with a `.pt` file and no way to use or compare it in the user-facing workflow is **not complete**. Provide a concrete, tested integration:

- Either load the explicitly selected approved model locally into the player with a compatible runtime, **or** provide a local CLI that processes the recording frame-by-frame into a clearly labelled non-destructive local inference cache plus a manifest that the existing player can load and synchronize by source hash, frame index, geometry, model/version and settings. Do not require the user to upload the recording. Predict disk usage before creating a large cache and ask before writing it.
- Show raw fixed-window, unchanged Argos 2 and the selected candidate/active CNN output on the exact same frame/sequence, with a clear model ID, whether it is unapproved/approved and an immediate classical bypass/rollback. Reject source/hash/frame-count mismatch; do not silently compare outputs from different frames. The user must be able to inspect complete sequences and artifacts, not only a single model snapshot.
- Include a tiny generated local recording in a scripted test: run actual inference from saved weights, load the result in the viewer, play/seek beyond frame 60, inspect matching frame identity, bypass the model and recover baseline. No production-quality or 25-fps claim follows from a test fixture. If full CNN inference in the browser is not practical, the local precomputed-cache approach is acceptable.

## 5. Reproducibility and acceptance tests

Provide a fresh-machine README, lockfiles or pinned platform-specific dependency instructions, actual executable CLI help and exact commands. A reviewer should be able to run on a Mac without accounts or footage. Add automated tests that cover at least:

1. Existing local player and all original six methods; original Argos 2 exact or tolerance-controlled parity against the archived engine at documented defaults on several synthetic frames, including a sequential reset/seek. Distinguish failures caused by mismatched defaults or temporal context.
2. Local input decoding, streaming full SHA-256, short/trailing files, endian/shift and exact frames, invalid inputs; do not claim support for unimplemented layouts.
3. Frame identity and stale result invalidation during source/decoder/frame/config changes; ROI coordinate mapping and export/import; no false save success on errors.
4. Full playback with >60 generated frames, seek/stop/end, selecting raw/Argos 2/CNN; explicit sequence context, no frame-index mix-up and reset behavior. Include at least one full-resolution generated-file test if resources permit.
5. Real stage toggles and comparison records; synthetic hard negatives; no made-up votes/results and no test-train context leakage. A numerical metric must be computed from data and labeled with its actual domain and sample size.
6. Dataset validation/leakage rejection, actual CNN weight update, finite inference, checkpoint reload/identity, baseline fallback, controlled promotion/failed-gate rejection and rollback, two-cycle demo and viewer integration. Include a test that no user footage/metadata is sent over a network in normal local use.

Run available tests and include their **actual stdout or an honest concise report** with commands, environment, pass/fail/skipped, resolutions and runtime. Report missing Playwright, MPS, Mac hardware or real-data tests explicitly. Do not report theoretical latency as measured performance. `npm ci` and training dependency installation may download software; do not download large external datasets or pretrained weights without permission.

## 6. Deliverable contract

Return one ZIP containing:

1. Full working updated source and ready-to-run local UI/player; do not supply only a handoff instruction or link to a remote deployment. Include a clear Mac setup/start path and files needed to reproduce it.
2. Actual offline training/evaluation/registry/inference source, sample dataset generator, dataset manifest examples, exact end-to-end demo commands and a small generated fixture or generator. The user's sample is not included.
3. Automated unit/integration/browser tests and dependency lockfiles or clearly explained pinned platform alternatives. Include local-use privacy and disk-space notes, failure handling and a rollback procedure. If a database is genuinely required, include authenticated local-only setup/migrations and test it; a dummy URL is not a database test. Prefer avoiding one.
4. A concise `RESULTS_AND_LIMITATIONS.md`: changes by path, which original code is unchanged and what is modified, exactly how inference connects to playback, actual test results, machine/dependency versions, synthetic-only metrics, failure cases, known limitations, and what a user must supply to run a real-data training cycle. State whether each acceptance criterion is PASS / PARTIAL / NOT IMPLEMENTED and why.
5. An honest user workflow: how to try the existing video, mark/review difficult frames, add trusted pairs, train, evaluate on validation, inspect, approve or reject, switch to the approved checkpoint, roll back, and later run a separate untouched final test. No automatic claims of improvement.

## 7. Specific failure traps found in the two prior submissions

- **Claude new lab:** no original six, no CNN, 16-bit controls with 14-bit histogram/window assumptions, overconfident ROI conclusions, stale ablation after settings/ROI changes, unauthenticated DB endpoints.
- **Argon new app:** hard-coded seeded A/B votes mixed with real reviews; “vote recorded” on HTTP 500; unsupported quantitative report claims; rewritten originals labelled untouched; Argos 2 detail-only ablation identical to disabled; sampled fingerprint called SHA-256; false full-16 decode; short file reported as a frame; frame-step modulo 60; local metadata can be sent to a remote DB; no implemented self-improvement training loop.
- **Current starting point:** helpful offline baseline but no CNN, no synchronized multimethod video playback, no validated temporal metric or general 16-bit support. Original-method tone maps and histories differ; per-frame evaluation resets temporal state; Argos 2 stage-1 bypass also disables bad-pixel handling. Existing test successes do not validate the user's file or physical temperature. Improve it rather than repeating these limitations as solved.

## 8. Final scientific and privacy boundaries

No real sample was provided. Do not claim a result on it, or that a model is ready for operational safety-critical use, or that an animal is hotter because it is brighter. Do not assume future frames are causal, adjacent noisy frames are independent Noise2Noise targets, or improvement in training loss establishes improvement on real recordings. The goal is **a working, repeatable, human-controlled improvement process**, not an impossible guarantee of monotonically increasing performance.
